Keyboard and screen reader lab

Use only the keyboard here. Each card lists what to test and the ARIA it uses. Prefer native HTML; ARIA fills gaps native elements cannot.

Tabs

Test: Tab to the module tabs above, then use Left, Right, Home and End. ARIA: tablist, tab, tabpanel, aria-selected, aria-controls, roving tabindex.

Accordion

Test: Enter or Space on a heading button. ARIA: aria-expanded, aria-controls.

Modal dialog

Test: Open it, press Tab (focus stays inside), press Esc (focus returns here). ARIA: native dialog with showModal() supplies the modal role, focus trap and Esc; aria-labelledby and aria-describedby name it.

Menu button

Test: Enter or Down Arrow opens; Up, Down, Home, End move; Esc closes and returns focus. ARIA: aria-haspopup, aria-expanded, menu, menuitem.

Form with validation

Test: Submit empty. Focus moves to the error summary; each link jumps to its field. ARIA: aria-required, aria-invalid, aria-describedby, role=status.

      Magnification, reflow and color vision

      SC 1.4.4 asks that text resize to 200% without loss of content or function. This is a simulation: also test with browser zoom, the OS magnifier, and a screen reader such as NVDA, JAWS or VoiceOver.

      How to test

      Keyboard only: Tab, Shift+Tab, Enter, Space, arrows, Esc. Screen readers: NVDA with Firefox or Chrome, VoiceOver with Safari, TalkBack on Android. Also check zoom to 200%, contrast tools, and automated scanners (axe DevTools, Lighthouse, WAVE). Automated tools find only a portion of WCAG issues, so manual testing is required.

      Choose Generate report to build a summary.

      Limits: this app cannot replace testing with real assistive technology, and its scanners check only what they can compute.
